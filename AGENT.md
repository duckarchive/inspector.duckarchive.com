# AGENT.md — Duck Archive Inspector

> **⚠️ KEEP THIS FILE UP TO DATE:** After making any change to the codebase (new routes, dependencies, scripts, env vars, conventions, directory structure, etc.), update the relevant section of this file in the same commit. This file is the single source of truth for AI agents working in this repo.

## Project Overview

**inspector.duckarchive.com** — a web app for exploring Ukrainian genealogy archives. It presents the archive hierarchy (Archive → Fond → Inventory → File) and tracks online availability of digitized materials across resources (e.g. FamilySearch DGS). Part of the Duck Archive ecosystem (duckarchive.com).

## Tech Stack

- **Framework:** Next.js 15 (App Router, Turbopack in dev), React 19, TypeScript 5.8
- **UI:** HeroUI v3 (single `@heroui/react` package + `@heroui/styles` CSS), Tailwind CSS 4, react-icons
- **Tables/Charts:** AG Grid (`ag-grid-react`, marked as `serverExternalPackages` in next.config.js), AG Charts
- **Maps:** Leaflet / react-leaflet + `@duckarchive/map`
- **Data:** PostgreSQL via Prisma 7 (`@prisma/client` + `@prisma/adapter-pg`), Zod 4 (schemas generated by `prisma-zod-generator`)
- **Auth:** NextAuth v4 with Google OAuth (`app/api/auth/[...nextauth]/route.ts`); access token kept in JWT/session. Server-side user lookup against external Duck API via `lib/user.ts` (`Authorization: Bearer` header → `DUCK_API_URL/api/user`)
- **i18n:** next-intl. Locales: `uk` (default, no URL prefix), `en`, `pl`, `cz`, `ro`, `es`, `it`. Config in `i18n/`, translations in `messages/*.json`. Locale resolution (middleware): URL prefix → `NEXT_LOCALE` cookie (1-year, see `localeCookie` in `i18n/routing.ts`) → `Accept-Language` → `uk`. Manual switches happen in `@duckarchive/framework`'s `DuckNav`/`SelectLocale`, which writes the same `NEXT_LOCALE` cookie client-side (soft navigations bypass the middleware's cookie sync) — keep cookie name/lifetime in sync between the two repos.
- **Data fetching (client):** SWR with fetchers from `lib/api.ts`
- **Shared org packages (installed from GitHub):** `@duckarchive/framework`, `@duckarchive/map`, `@duckarchive/prisma`
- **Typography:** lives in `@duckarchive/framework/fonts` (the package also ships the SF Pro / CCJimLee binaries) and is applied in `app/layout.tsx`. `next/font` is a **compile-time** transform Next skips inside `node_modules`, so `@duckarchive/framework` must stay in `transpilePackages` (next.config.js) or the loaders go untransformed and throw at runtime. Font `src`/option values in that package must stay explicitly written literals — no template strings or shared path constants.
- **Package manager:** pnpm (see `pnpm.onlyBuiltDependencies` in package.json)

## Prisma Specifics (important)

- The schema does **not** live in this repo. `prisma.config.ts` points to `node_modules/@duckarchive/prisma/prisma/inspector/schema.prisma` (shared `@duckarchive/prisma` package).
- Generated client goes to `generated/prisma/client`, generated Zod schemas to `generated/prisma/zod`. Import via the `@generated/*` path alias (e.g. `import { PrismaClient } from "@generated/prisma/client/client"`).
- DB access goes through the singleton in `lib/db.ts` (PrismaClient with `PrismaPg` adapter).
- To change the DB schema, change the `@duckarchive/prisma` package, then reinstall/regenerate here.

## Conventions

- **Path aliases:** `@/*` → repo root, `@generated/*` → `generated/`.
- **API route pattern:** each `app/api/...` level pairs `route.ts` (HTTP handler) with `data.ts` (data-access logic). Follow this split when adding endpoints.
- **Archive codes in URLs** are Cyrillic-capable — see `useCyrillicParams` hook for decoding route params.
- **Pages:** every archive-hierarchy page level has a `loading.tsx`. `[archive-code]` also has `opengraph-image.tsx`.
- **Linting:** flat ESLint config (`eslint.config.mjs`) with prettier, react-hooks, unused-imports, jsx-a11y. Run `pnpm lint` before committing (it auto-fixes).
- **UI components:** import everything from `@heroui/react` (v3 is one package). Components are compound — `Modal.Backdrop`/`Modal.Container`/`Modal.Dialog`, `TextField` + `Label` + `Input`, `Accordion.Item`/`Trigger`/`Panel`. There is no `HeroUIProvider`.
- **Styling:** no `tailwind.config.js` — Tailwind v4 is configured CSS-first in `styles/globals.css` (`@theme` for the DESIGN.md scales, `@source` for the `@duckarchive/*` packages, `@layer theme` for the HeroUI colour tokens). Colour utilities are v3 semantics: `accent` (not `primary`), `surface`/`overlay` (not `content1-4`), `muted` (not `default-400/500`); numbered colour scales no longer exist.
- **Routing links:** HeroUI v3 `Link` has no router integration, so internal navigation uses `next/link` with `className="link"` (the HeroUI link style). Use HeroUI `Link` only for external/`mailto:`/`tel:` targets, with explicit `target`/`rel`.
- **Loading buttons:** v3 `Button` has no built-in spinner — use `components/pending-button.tsx` (`isPending`) instead of v2's `isLoading`.
- **Localization:** any user-facing string must be added to all 7 files in `messages/`, with **identical `{placeholder}` names in every locale** — a mismatch throws `FORMATTING_ERROR` at runtime only for that locale (this happened in prod with `en.json`'s `{fileTitle}` vs `{caseTitle}` everywhere else). Default locale `uk` is served without a URL prefix (`localePrefix: "as-needed"`). The public UI is fully keyed (search page, tables, modals, guide); intentionally NOT localized: `/editor` (uk-only), `/friends` + `useNoRussians` texts (ru-directed on purpose), the iframe embed page, `TYPE_LABEL` in `resource-badge.tsx` (CSV export only — display goes through the `resource-badge` message namespace), catalog example placeholders (`ДАХмО-Р6193-5-1`, home-search typewriter examples — the catalog is Cyrillic). Tag chips display via the `tags` namespace (keys are the raw Cyrillic tag values; the API always receives the raw values). AG Grid chrome: `DuckTable` defaults to its Ukrainian locale; `components/table.tsx` overrides `localeText` to AG Grid's English for non-uk locales.
- **Content translation (foreigners):** catalog text is never translated at rest — `lib/translate.ts` drives Chrome's built-in **Translator API** (on-device, Chrome 138+/Edge 148+ **desktop only**) as a read-time gist layer. `ContentTranslationProvider` (mounted in `app/providers.tsx`) owns the on/off state and exposes `targetLanguage` for the `lang` attribute, defaults **on** for foreign readers when the pair is already `available` (a `downloadable` pair still waits for the button — Chrome will not download outside a user gesture), persists a tri-state preference in `localStorage` (`"0"` = explicit opt-out, absent = default on), and hides itself entirely for `uk` readers, on mobile viewports (`useIsMobile`, <640px — the API is desktop-only), and wherever `Translator.availability()` says `unavailable`. The mobile gate lives in the provider, not the button, so resizing narrow also turns an active session back off rather than stranding it with no control. `PagePanel` takes `isTranslatable` (the four catalog tables pass it) to render `<TranslatableText>` around title/info plus the `<TranslateToggle>` button; `<TranslatableText>` is also used for search-result titles, file-page author labels, archive names in the archives list, and the archive-picker subtitle — always around prose only, never around codes (`full_code`, archive `code`) or around a value fed back into a query — the press doubles as the user gesture Chrome demands before downloading a language pack. Translation **replaces** the text in place while enabled (no extra line, no layout shift); the Cyrillic original stays reachable as the element's `title` tooltip, since it is the citable record. Any page that renders translatable content must also render a `<TranslateToggle>`, or a default-on reader gets translated text with no way to turn it off. Gotchas: our locale `cz` must map to BCP-47 `cs` (`toBcp47`); the glossary is **source-side only** (expanding `с.`→`село`, `Ревізька казка`→`ревізійний перепис` — fixing model *output* with regexes was tried and fails, the wording varies by context); citation shorthand `ф./оп./спр.` is deliberately left alone (expanding it yields the worse "(315 Fund)"); JS `\b` never matches before Cyrillic, so the glossary uses an explicit boundary group. Typings live in `types/translator.d.ts`.
- **Latin search input (foreigners):** the API's no-Latin rule is untouched — conversion is client-side only (`lib/translit.ts`): `toCyrillicQuery(text, locale)` for free-text fields (locale-aware reverse transliteration: en/KMU-2010 base + pl/cz/ro/es/it overlays, NFD fallback so no Latin ever leaks), `foldCodeInput` for fond/inventory/file codes (homoglyph fold then phonetic), `buildArchiveCodeResolver` for archive codes (closed-set aliases, `DAKHMO → ДАХмО`). Wired in `components/search.tsx`, `components/home-search.tsx` (with a live «searching as: …» hint via `search-page.translit-hint`), `hooks/useSearch.tsx` (the `?q=` path used by both quick-search boxes), and the author autocompletes. Converted values replace the field content on submit so the user sees the actual query (FamilySearch pattern).
- **CORS:** API is consumed cross-origin by duckarchive.com and a Chrome extension — allowlist lives in `middleware.ts`.

## Naming Migration (fund→fond) — switchover state

The `fund → description → case` ⇒ `fond → inventory → file` migration is promoted to prod (2026-07-29) and the app switched over:

- **Pages:** `/archives/...` URLs are kept (SEO) but render the new structure: `archives/[archive-code]/[fond-code]/[inventory-code]/[file-code]`. The `/catalog` page tree was deleted outright (no redirect). Components: `archive-table` / `fond-table` / `inventory-table` / `file-table`; hooks: `useArchive` / `useFond` / `useInventory` / `useFile` — all read `/api/catalog/*`.
- **APIs:** `/api/catalog/*` is the canonical API and the only one the app itself uses; `GET /api/catalog` (flat `Archive[]`, ordered by code) replaced the old `/api/archives` list endpoint — it is also consumed by **duckarchive.com** (`INSPECTOR_API_URL/api/catalog`), so keep it stable. Everything under `/api/archives/*` (list and the legacy fund/description/case tree) is gone.
- **Public API input rule (`lib/validate.ts`):** every free-text value (search fields, `authors?q=`, catalog path codes) is rejected with 400 if it contains a Latin letter — the catalog holds only Cyrillic data, so this is a hard validation rule that also shuts out anything injection-shaped before it reaches the DB (queries are parameterised anyway). Search bodies are zod-validated (`searchRequestSchema`, strict).
- **Search text matching:** `title` covers `files.title`, `files.info` and linked `authors.title`/`authors.info`; `place` covers `files.info` + `authors.title`; `author` covers `authors.title`. `fuzziness` (0.3–1, floor enforced server-side) switches ILIKE to pg_trgm word similarity (`needle <% column`, GIN trgm indexes on files.title/info and authors.title) with `SET LOCAL pg_trgm.word_similarity_threshold` inside one transaction; the search page exposes it as match-strictness presets (100 % = substring, 80/60/40/30 % = threshold × 100) in a `ButtonGroup` split button next to «Пошук»; the form is only submitted when a real criterion is set (`hasSearchCriteria`, fuzziness alone doesn't count) and the API answers 400 to a body without criteria (an unfiltered GROUP BY over all files takes ~40 s) (`FUZZINESS_OPTIONS` in `components/search.tsx`). The single `year` param is gone (400 as unknown field); `useSearch` still rewrites old `?year=` links into `year_from`/`year_to`. LIKE wildcards in user text are escaped.
- **Search:** `/api/search` queries `files` (+`file_years`, `file_authors`, `authors`, `file_locations`, `online_copies`). Request keys are `fond`/`inventory`/`file`; `useSearch` still rewrites inbound legacy `fund`/`description`/`case` query params. Geo-radius search is live: a file matches through its own `file_locations` OR any linked author's coordinates (authors carry the geocoded church/parish points).
- **Removed:** `/online-copy-search` page + `/api/online-copy-search` + `lib/online-copy-query.ts` (hard 404, no redirect).
- **Hot-path DB rules:** catalog pages must not run aggregate queries per request. Tag vocabulary comes from `generated/search-vocab.json` (built by `scripts/generate-stats.ts` on `prebuild`/`predev`), never from a live `UNNEST(tags)` scan. Per-resource online-copy counts live behind `unstable_cache` (1h) in `data/resources.ts` (`getResourcesWithCounts`, only `/resources` needs them); everything else uses `getResources()` (metadata only).
- The legacy `funds`/`descriptions`/`cases` tables (and their `*_years`/`*_online_copies`/`case_authors` companions) were dropped from the DB and the schema in `@duckarchive/prisma` 6.0.0; only the `fonds`/`inventories`/`files` tree exists. Expression/partial indexes Prisma can't declare (`file_locations_geog_idx`, `authors_geog_idx`, `online_copies_public_by_resource_idx`) live in raw migrations there — keep the geo query text in `app/api/search/route.ts` identical to the index expression or the planner won't use it.

## In-Progress Work

- **Editor feature:** `editor-feature.md` is the spec for community catalog editing (action queue in `file_actions`/`inventory_actions`, viewer/editor/admin roles, admin-moderated execution). Implemented on this branch as admin-only `/editor`; the Duck API `is_editor` role lands separately.
- **Online-copies autolink:** `/editor/online-copies` has an «Автопривʼязка» button → `GET/POST /api/editor/online-copies/autolink`. It matches unlinked `online_copies.parsed` against `files.full_code` AND constructed inventory codes (архів-фонд-опис — inventories store no full_code) in SQL, with per-copy priority file direct → том/частина fallback → inventory direct → file-range truncation. Strict = verbatim equality; wide adds FS-blob extraction, homoglyph/Р-prefix folding, том/частина, `(опис)` markers and справи-ranges — rules from the 2026-08-05 bulk linking (validated ≥99.5% against existing links). Confirm bulk-inserts pending `connect_to_online_copy` actions into `file_actions`/`inventory_actions` in one statement for admin review (`ON CONFLICT DO NOTHING` against the partial unique indexes makes re-runs idempotent). Both handlers fold millions of rows (~1.5min preview / ~3min insert), hence `maxDuration = 300` and the waiting modal. The `guarded` CTE holds back a match whose url is already linked to the proposed target through another row (reported as `already_linked` in the preview).
- **Online-copy identity (`@duckarchive/prisma` 6.5.0, migration `20260901120000_online_copies_source_key`):** an `online_copies` row is one (url ↔ target) edge. Its identity is `(resource_id, url, source_key)` — `source_key` is the scraper's stable id of the claim within the url (FamilySearch image-group id, libraria number id, …; the code text itself for sources without ids), and `parsed` is a **mutable** claim text the scraper refreshes in place, so a reworded source no longer mints a twin next to a linked row. `source_key IS NULL` = editor-owned row (`add_online_copy`, FS imports) — never a scraper claim. The DB enforces `UNIQUE (resource_id, url, source_key)` and one row per `(resource_id, url, file_id | inventory_id)` (partial uniques). Consequences in this app: `connect_to_online_copy` / `add_online_copy` / merges first look for the row already holding that edge and **fold the copy into it** (`adoptCopyInto` in `app/api/editor/actions/[entity]/[id]/data.ts`: the linked row survives, takes the twin's `source_key`+`parsed` when the twin is the fresher scraper row, history is repointed, the twin is deleted); a residual `P2002` on resolve is a 409, not a 500. Never delete a keyed twin without moving its `source_key` to the survivor — the next sync re-mints it. `*_actions.online_copy_id` is `ON DELETE SET NULL` now (history survives a copy delete). One-time cutover scripts + the pre-flight/violator queries: `migration/2026-09-01-oc-source-key-cutover/`.
