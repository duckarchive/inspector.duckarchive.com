# AGENT.md — Duck Archive Inspector

> **⚠️ KEEP THIS FILE UP TO DATE:** After making any change to the codebase (new routes, dependencies, scripts, env vars, conventions, directory structure, etc.), update the relevant section of this file in the same commit. This file is the single source of truth for AI agents working in this repo.

## Project Overview

**inspector.duckarchive.com** — a web app for exploring Ukrainian genealogy archives. It presents the archive hierarchy (Archive → Fond → Inventory → File) and tracks online availability of digitized materials across resources (e.g. FamilySearch DGS). Part of the Duck Archive ecosystem (duckarchive.com).

## Tech Stack

- **Framework:** Next.js 15 (App Router, Turbopack in dev), React 19, TypeScript 5.8
- **UI:** HeroUI v3 (single `@heroui/react` package + `@heroui/styles` CSS), Tailwind CSS 4, react-icons
- **Tables/Charts:** AG Grid (`ag-grid-react`, marked as `serverExternalPackages` in next.config.js), AG Charts
- **Maps:** Leaflet / react-leaflet + `@duckarchive/map`
- **Data:** PostgreSQL via Prisma 7 (`@prisma/client` + `@prisma/adapter-pg`), Zod 4 (schemas generated by `prisma-zod-generator`)
- **Auth:** NextAuth v4 with Google OAuth (`app/api/auth/[...nextauth]/route.ts`); access token kept in JWT/session. Server-side user lookup against external Duck API via `lib/user.ts` (`Authorization: Bearer` header → `DUCK_API_URL/api/user`)
- **i18n:** next-intl. Locales: `uk` (default, no URL prefix), `en`, `pl`, `cz`, `ro`, `es`, `it`. Config in `i18n/`, translations in `messages/*.json`. Locale resolution (middleware): URL prefix → `NEXT_LOCALE` cookie (1-year, see `localeCookie` in `i18n/routing.ts`) → `Accept-Language` → `uk`. Manual switches happen in `@duckarchive/framework`'s `DuckNav`/`SelectLocale`, which writes the same `NEXT_LOCALE` cookie client-side (soft navigations bypass the middleware's cookie sync) — keep cookie name/lifetime in sync between the two repos.
- **Data fetching (client):** SWR with fetchers from `lib/api.ts`
- **Shared org packages (installed from GitHub):** `@duckarchive/framework`, `@duckarchive/map`, `@duckarchive/prisma`
- **Typography:** lives in `@duckarchive/framework/fonts` (the package also ships the SF Pro / CCJimLee binaries) and is applied in `app/layout.tsx`. `next/font` is a **compile-time** transform Next skips inside `node_modules`, so `@duckarchive/framework` must stay in `transpilePackages` (next.config.js) or the loaders go untransformed and throw at runtime. Font `src`/option values in that package must stay explicitly written literals — no template strings or shared path constants.
- **Package manager:** pnpm (see `pnpm.onlyBuiltDependencies` in package.json)

## Commands


## Prisma Specifics (important)

- The schema does **not** live in this repo. `prisma.config.ts` points to `node_modules/@duckarchive/prisma/prisma/inspector/schema.prisma` (shared `@duckarchive/prisma` package).
- Generated client goes to `generated/prisma/client`, generated Zod schemas to `generated/prisma/zod`. Import via the `@generated/*` path alias (e.g. `import { PrismaClient } from "@generated/prisma/client/client"`).
- DB access goes through the singleton in `lib/db.ts` (PrismaClient with `PrismaPg` adapter).
- To change the DB schema, change the `@duckarchive/prisma` package, then reinstall/regenerate here.

## Conventions

- **Path aliases:** `@/*` → repo root, `@generated/*` → `generated/`.
- **API route pattern:** each `app/api/...` level pairs `route.ts` (HTTP handler) with `data.ts` (data-access logic). Follow this split when adding endpoints.
- **Archive codes in URLs** are Cyrillic-capable — see `useCyrillicParams` hook for decoding route params.
- **Pages:** every archive-hierarchy page level has a `loading.tsx`. `[archive-code]` also has `opengraph-image.tsx`.
- **Linting:** flat ESLint config (`eslint.config.mjs`) with prettier, react-hooks, unused-imports, jsx-a11y. Run `pnpm lint` before committing (it auto-fixes).
- **UI components:** import everything from `@heroui/react` (v3 is one package). Components are compound — `Modal.Backdrop`/`Modal.Container`/`Modal.Dialog`, `TextField` + `Label` + `Input`, `Accordion.Item`/`Trigger`/`Panel`. There is no `HeroUIProvider`.
- **Styling:** no `tailwind.config.js` — Tailwind v4 is configured CSS-first in `styles/globals.css` (`@theme` for the DESIGN.md scales, `@source` for the `@duckarchive/*` packages, `@layer theme` for the HeroUI colour tokens). Colour utilities are v3 semantics: `accent` (not `primary`), `surface`/`overlay` (not `content1-4`), `muted` (not `default-400/500`); numbered colour scales no longer exist.
- **Routing links:** HeroUI v3 `Link` has no router integration, so internal navigation uses `next/link` with `className="link"` (the HeroUI link style). Use HeroUI `Link` only for external/`mailto:`/`tel:` targets, with explicit `target`/`rel`.
- **Loading buttons:** v3 `Button` has no built-in spinner — use `components/pending-button.tsx` (`isPending`) instead of v2's `isLoading`.
- **Localization:** any user-facing string must be added to all 7 files in `messages/`, with **identical `{placeholder}` names in every locale** — a mismatch throws `FORMATTING_ERROR` at runtime only for that locale (this happened in prod with `en.json`'s `{fileTitle}` vs `{caseTitle}` everywhere else). Default locale `uk` is served without a URL prefix (`localePrefix: "as-needed"`).
- **CORS:** API is consumed cross-origin by duckarchive.com and a Chrome extension — allowlist lives in `middleware.ts`.

## Gotchas

- `generated/` is produced by `pnpm prisma:generate` — never hand-edit; regenerate after dependency updates.
- The Prisma schema is inside `node_modules` (from `@duckarchive/prisma`), so `pnpm install` order matters: `postinstall` runs generation automatically.
- `ag-grid-community` must stay in `serverExternalPackages` (next.config.js) or the build breaks.
- Build uses `staticPageGenerationTimeout: 300` and `staticGenerationMaxConcurrency: 2` — static generation of archive pages is heavy; be careful adding more `generateStaticParams`.
- README.md is the stale Next.js/NextUI template readme — don't trust it for project info; trust this file.

## Naming Migration (fund→fond) — switchover state

The `fund → description → case` ⇒ `fond → inventory → file` migration is promoted to prod (2026-07-29) and the app switched over:

- **Pages:** `/archives/...` URLs are kept (SEO) but render the new structure: `archives/[archive-code]/[fond-code]/[inventory-code]/[file-code]`. The `/catalog` page tree was deleted outright (no redirect). Components: `archive-table` / `fond-table` / `inventory-table` / `file-table`; hooks: `useArchive` / `useFond` / `useInventory` / `useFile` — all read `/api/catalog/*`.
- **APIs:** `/api/catalog/*` is the canonical new-structure API and the only one the app itself uses. `/api/archives` (list only, no `[archive-code]`+ tree) is kept because editor pages/`instance-picker` still call it. The legacy fund/description/case-shaped deep endpoints (`/api/archives/[archive-code]`, `.../[fund-code]`, etc.) were deleted — no external consumer needed them preserved.
- **Search:** `/api/search` queries `files` (+`file_years`, `file_authors`, `authors`, `file_locations`, `online_copies`). Request keys are `fond`/`inventory`/`file`; `useSearch` still rewrites inbound legacy `fund`/`description`/`case` query params. Geo-radius search is live: a file matches through its own `file_locations` OR any linked author's coordinates (authors carry the geocoded church/parish points).
- **Removed:** `/online-copy-search` page + `/api/online-copy-search` + `lib/online-copy-query.ts` (hard 404, no redirect).
- The legacy `funds`/`descriptions`/`cases` tables (and their `*_years`/`*_online_copies`/`case_authors` companions) were dropped from the DB and the schema in `@duckarchive/prisma` 6.0.0; only the `fonds`/`inventories`/`files` tree exists. Expression/partial indexes Prisma can't declare (`file_locations_geog_idx`, `authors_geog_idx`, `online_copies_public_by_resource_idx`) live in raw migrations there — keep the geo query text in `app/api/search/route.ts` identical to the index expression or the planner won't use it.
