# Step 5 — proposal: mechanical fixes for the 669 step-4 leftovers (2026-08-06)

Input: the 669 `review` rows of `step4-decision-log.csv` (items acmb could not
resolve). 661 have pure-digit codes and were classified in
`step5-classification.csv` (generated by `step5_classify.py` / `step5_enrich.py`
in the session scratchpad); 8 have non-digit codes or fell out of the worklist.

Classifier: enumerate splits `code = B‖S` (B = справа candidate, no leading
zero, `B ≤ max(5·p95, p95+100)`), then classify in priority order. `tgt_exists`
/ `c_exists` = does a file with that integer code already exist in the same
inventory (live DB check, letter-coded files excluded).

## Auto-fixable — 303 rows

| group | n | rule | action |
|---|---|---|---|
| self-year | 10 | unique split whose 4-digit suffix lies within the file's own recorded year range (±2), e.g. `ДАХО-40-105-2261852` = спр. 226 + 1852 (years 1851) | 6 rename, 4 merge |
| pair, both free | 61 | equal-length halves `B < C` (range 49, adjacent 29→12), neither exists: `ДАВіО-172-2-559580` = 559‖580 «Вибули» | rename → B |
| pair, B exists | 232 | same shape, leading half already a file (range B1C0 32 + B1C1 183, adjacent B1C1 17): `ДАВоО-35-2-117566` = 117‖566 | merge → B |

- **self-year** is the same rule acmb confirmed 33× in step 3 («confirmed-year-glue»).
- **equal-split pairs**: both readings — справа + аркуші (page-count glue) and
  справи-range glue on «Вибули» placeholder rows (64 of them) — point at the
  same leading number B. The failure mode (previous catalog line's number glued
  *before* the real справа → true home would be C) had a ~0.7% base rate in the
  acmb post-verification of step 3 (2 of 305).
- Renames are collision-free and logged (old code kept in the decision log);
  merges reuse the proven step-3/4 transaction: copies relinked
  (unique-guarded), years/locations/authors moved, title copied onto empty
  bases, anomaly row backed up to CSV before deletion.
- 44 of the 303 carry online copies — relinking covered by the merge SQL.
