# 2026-08-25 — ЦДНТА: справжнє дерево з cdnta-old.archives.gov.ua + повний relink

Applied 2026-08-25 against local inspector DB (localhost:5555). All three batches COMMITted.

## Проблема

Дерево ЦДНТА в БД було хибним: створене 2026-08-05 (`migration/2026-08-05-online-copies-linking/link-ranges.sql` PART A)
обрізанням FS-кодів до перших 3 сегментів, що прийняло **№ комплексу** (напр. `3-36`) за опис-справу.
Було: 4 фонди × 1 опис «3», 2 056 файлів (1 953 сироти без копій), 5 935 копій на 4 «файлах-комплексах»,
102 файли зі сміттєвим тайтлом FS-колекції та систематично здубльованими лінками (9 копій × ~29 файлів),
279 stale pending `inventory_actions`.

## Джерело

5 сторінок описів (Cloudflare — тягнеться лише через Chrome; same-origin fetch + rowspan-grid парсер):
opisi-2 (524 рядки), opisi-3 (184), opisi-4 (4), opisi-5 (1), opisi-fop (36) → `source/rows.tsv`
(749 описів; SHA-256 звірено з браузерною копією: `99f579e3…`).

Семантика FS-кодів (підтверджена 94.3% in-range на 6-токенних):
`Р-107-3-36-4-1428` = фонд Р-107, комплекс 3-36, **опис 4**, справа 1428;
`Р-17-3-9-119` = фонд Р-17, комплекс 3-9, справа 119 → опис через діапазони од.зб.

## Ухвалені рішення (сесія 2026-08-25)

1. **Код опису** = № опису; дублікати в межах фонду отримують кириличний постфікс у порядку появи
   в таблицях: `Р20-1` (к.2-2 «Парова турбіна ВК 100-4»), `Р20-1А` (к.2-3 «Поворотно-лопатева…»), …
   Алфавіт: АБВГҐДЕЄЖЗИІЇЙКЛМНОПРСТУФХЦЧШЩЮЯ (+ двобуквений overflow; макс. фактично `1Ш` у Р-188 з 30 комплексами).
2. **Файли**: створено ВСІ од.зб. з діапазонів (bare rows: code + full_code) — 135 389 + 341 gap-файлів з relink.
3. fond.title: «Назва комплексу» для однокомплексних фондів, «Назва фонду» для ФОП, NULL для багатокомплексних.
   inventory.title = назва комплексу; inventory.info = `к. <комплекс>, од.зб. <діапазони>`.
4. Новий ресурс `website_cdnta` (WEBSITE); кожен PDF опису = online_copy на опису,
   parsed = `ЦДНТА-<фонд>-<опис> (опис)`, availability PUBLIC. 780 копій (описи з кількома PDF-частинами — 22 шт.).
